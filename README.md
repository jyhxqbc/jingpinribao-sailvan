# 精品日报

Chrome Manifest V3 本地经营分析扩展，147图标，版本3.5.2。

完整说明：[精品日报原理以及使用说明.md](精品日报原理以及使用说明.md)。

## 构建与安装

下载的成品目录（包含manifest.json）可直接在Chrome加载；GitHub成品仓库根目录即扩展目录。下面构建命令仅适用于包含package.json和src的源码工程。

```powershell
npm install
npx playwright install chromium
npm run build:extension
npm run build:release
```

在Chrome的 `chrome://extensions` 开启开发者模式，加载本项目 `dist-extension`。`build:release` 还会生成正常版与混淆分发版两个ZIP；两版保持相同扩展ID，更新时重新加载同一扩展，不卸载、不更换Manifest公开key。无需启动服务器。

分发包解压后选择直接含 `manifest.json` 的目录加载。公开成品仓库同时提供正常版与混淆分发版两个ZIP，根目录是混淆版。不要同时加载两个版本：它们使用同一扩展ID。混淆处理应用JS及导入/备份worker，不处理第三方DuckDB运行时、WASM、HTML或CSS；不生成源码映射。

**保护边界：** 浏览器必须能执行扩展代码，因此这不是加密。仓库同时公开正常版，任何人都可以直接分析未混淆代码；混淆分发版仅适合单独分发时提高逆向成本，不提供仓库层面的保密。旧提交中也已有未混淆版本和规则文档。需要真正保密的规则应迁到受控服务端。

## 本版规则

3.5.2将“月份对比”升级为可按日/按月切换的“对比图表”；经营汇总对象对比可直接绘图，多对象图卡每页最多8张，每图可导出PNG/CSV。发布脚本生成正常版和混淆分发版两个ZIP；两者都发布到成品仓库。浏览器必须执行可读取的JavaScript，混淆不能提供不可破解的加密保护。

3.5.1将月份、SPU筛选固定在顶部。选月份后切按日期会自动填写仓库实际日期，优先主表、VCPO独有月用VCPO；不连续月份限制继续生效，手动改日期也不混入跳过月份。恢复全部日期同时清除月份限制。左右轴采用一致的单位校验：同单位自由放置，不同单位冲突阻止并提示，支持一键交换，空轴隐藏；超过两种单位明确提示。三处图表轴配置分别随仓库保存。

3.5兼容VCPO“月份”表头、缺日期和缺转换列；仅在月份可确定时补为1日，数据质量保留依据，已有完整日期不改。1—10月四来源表头及VCPO逐行验证见 [兼容说明](VCPO_COMPATIBILITY_20261022.md)。单对象月份对比支持最多两指标合图、左右双轴与柱线；所有折线相关图可开启平滑并保存设置。

3.4新增可组合的月份透视、全局不连续月份多选与按月/按日期模式。图表分析新增多对象月份对比，每指标独立柱状/折线图及月份横排表，支持排序导出、无记录与真实0区分、主表日期覆盖提示和完整设置记忆。月份含年份，原日期区间保留，月比率按汇总分子/分母计算。

3.3.1修复7/8月旧版促销表头误判：实时表可缺少非计算用的“新旧料号转换”；已入账兼容旧列名Original balance并保留原金额，不自动换汇。空表与缺表分开标记，兼容依据写入数据质量。旧版已误判的7/8月文件需重新导入，主表仍去重；详见 [四文件调查](PROMOTION_SOURCE_AUDIT_20261021.md)。

- 一个XLSX包含主合并表、VCPO、实时促销、已入账促销四Sheet，均按表头识别，可改名、换序、重排唯一字段或增加说明行。
- 初次导入必须有主表；已有对应期间主表后可只补费用，预览明确确认期间及空表含义。
- 四来源独立去重与修订；促销缺表/空表让本次涉及整月该来源按0，历史暂停保留，补源默认替换或可选合并；VCPO及费用独有对象仍保留。
- 指标以每日销售数据-集合为依据，默认SPU为主表AZ/VCPO AJ，原AQ/AA作为独立维度。
- 默认原日报对账范围，可切换全部有效记录；保留Excel文本通配符对数字0的区别。
- 参数始终按月份自动填写，CNY按月推导不足用6.6，VCPO除数1.14、UK乘数0.74、SKU比例0.03为明确默认，逐字段记录来源；支持指定模板强制覆盖全部月份。未使用的两个天数输入移除。
- 站外推广全局固定0，含旧库数据，页面及导出明确标记已排除。全站原币TOTAL按原表使用USD值并说明。
- 原日报对账页面/TOTAL入口移除，两种分析范围保留；日期旁可只重置日期。
- 数据质量按月份和文件展示四来源状态、归零事件、默认/推导/手动参数依据。透视数值旁不再展示参考小字，真实错误仍--，说明随分析导出保留。
- 完整仓库与SQL默认无损gzip压缩（json.gz/sql.gz），保留历史；兼容恢复旧JSON/SQL，SQL解压后仍可用于SQLite。
- 旧库升级有预览与备份入口，原始值、批次和历史不丢弃。
- 三层毛利分别展示，总推广占比纳入默认列；库存三项移除。
- 经营汇总/日期汇总分别记住指标和顺序，可恢复默认；配置随仓库及完整SQL/JSON备份迁移。
- 经营概览支持最多12项独立面板指标、调整先后、自适应排版，配置随仓库保存。

## 验证与维护

```powershell
npm test
npx playwright test tests/e2e/two-sources.spec.ts tests/e2e/extension.spec.ts
```

实际来源及公式证据：[TWO_SHEET_RECONCILIATION.md](TWO_SHEET_RECONCILIATION.md)。程序验收：[VALIDATION.md](VALIDATION.md)。原业务Excel只读核对，不随扩展发布。

IndexedDB保存原始与事实，OPFS Parquet作为可重建磁盘分析层。每次读取10,000行，约100,000行分片；查询512MB预算、128MB压缩缓存、16项查询缓存、50,000组结果上限。单Excel128MB、单来源Sheet200,000行，XLSX源数据导出合计100,000行，更大仓库使用完整备份。

源代码位于 `src/`，MV3入口位于 `extension/`，构建脚本位于 `scripts/`，本地WASM位于 `public/`。只维护扩展发布目录，`npm run build`也构建扩展。开发服务器仅用于源码调试。

历史Markdown保留Excel证据；与现版冲突的旧描述以完整说明及3.3验收为准。卸载扩展、清理浏览器数据会丢失仓库，更新前请备份。
